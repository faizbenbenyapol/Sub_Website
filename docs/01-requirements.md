## 1. ภาพรวม

### ปัญหา
1. สมัครบริการรายเดือนไว้หลายเจ้า แล้ว**ลืมว่าสมัครอะไรไว้บ้าง** และไม่รู้ว่ารวมแล้วจ่ายเดือนละเท่าไร
2. **ลืมยกเลิกช่วงทดลองใช้ฟรี** แล้วโดนตัดเงินโดยไม่ตั้งใจ
3. หาร Family Plan กับเพื่อนแล้ว**ต้องตามทวงเงินทุกเดือน** และจำไม่ได้ว่าใครจ่ายแล้วบ้าง
4. ข้อมูลราคาเป็นเงินบาท ข้อมูลแพ็กเกจ และวิธียกเลิกของแต่ละบริการกระจายอยู่คนละที่

### เป้าหมาย
- ผู้ใช้เห็นค่าใช้จ่ายรวมจาก subscription ทั้งหมดในหน้าเดียว
- ได้รับอีเมลแจ้งเตือนก่อนถูกตัดเงินและก่อนช่วงทดลองใช้ฟรีหมด
- หารค่าบริการกับเพื่อนได้ โดยให้เพื่อนสแกน QR พร้อมเพย์จ่ายส่วนของตัวเอง
- มีคลังข้อมูลบริการ subscription ในไทยที่ Admin ดูแลให้เป็นปัจจุบัน

### ตัวชี้วัดความสำเร็จ (สำหรับ demo)
- ทำ flow หลักได้ครบตั้งแต่ต้นจนจบโดยไม่มี error: สมัคร → เพิ่ม subscription → เห็นใน Dashboard → ได้รับอีเมลแจ้งเตือน
- QR พร้อมเพย์ที่สร้างขึ้น สแกนด้วยแอปธนาคารจริงแล้วแสดงชื่อผู้รับและยอดเงินถูกต้อง
- ใช้งานบนมือถือ (375px) และ desktop (1280px) ได้สมบูรณ์

## 2. ผู้ใช้ (Personas)

| ผู้ใช้ | ลักษณะ | สิ่งที่ต้องการ |
|---|---|---|
| **Guest** | ยังไม่สมัครสมาชิก | ดูคลังข้อมูลบริการ ราคา และวิธียกเลิก |
| **User** | นักศึกษา/คนทำงาน มี subscription 3–10 รายการ | รวมรายการไว้ที่เดียว ได้รับแจ้งเตือน และหารค่าบริการกับเพื่อน |
| **Admin** | ผู้ดูแลระบบ | จัดการคลังข้อมูลบริการ ดูแลผู้ใช้ และดูภาพรวมผ่าน Dashboard |

## 3. User Stories + Acceptance Criteria

ลำดับความสำคัญ: **P0** = ต้องมีก่อนส่ง (ครบโจทย์) | **P1** = ฟีเจอร์เด่น ทำหลัง P0 เสร็จ | **P2** = ถ้ามีเวลา

### A. Authentication (P0)

**US-A1** ในฐานะ Guest ฉันต้องการสมัครสมาชิกด้วยอีเมลและรหัสผ่าน เพื่อบันทึก subscription ของฉัน
- Given กรอกชื่อ อีเมล และรหัสผ่าน (≥ 8 ตัว) ครบ When กดสมัคร Then ระบบสร้างบัญชี role `user` และพาเข้าสู่ระบบ
- Given อีเมลซ้ำกับที่มีอยู่ When กดสมัคร Then แสดงข้อความ "อีเมลนี้ถูกใช้แล้ว"
- รหัสผ่านต้องถูก hash ก่อนบันทึกลงฐานข้อมูล

**US-A2** ในฐานะ User/Admin ฉันต้องการเข้าสู่ระบบและออกจากระบบ
- Given อีเมลหรือรหัสผ่านผิด When กดเข้าสู่ระบบ Then แสดงข้อความ error โดยไม่บอกว่าผิดช่องไหน
- Given เข้าสู่ระบบด้วย role `admin` Then เห็นเมนูหลังบ้าน (`/admin`)

**US-A3** ในฐานะระบบ ต้องป้องกันการเข้าถึงที่ไม่มีสิทธิ์
- Given ยังไม่เข้าสู่ระบบ When เข้า `/dashboard` Then ระบบพาไปหน้าเข้าสู่ระบบ
- Given role `user` When เข้า `/admin` หรือเรียก API ของ admin Then ได้ 403
- Given User A When พยายามแก้หรือดูข้อมูลของ User B ผ่าน API Then ได้ 403/404

### B. คลังข้อมูลบริการ — ฝั่งผู้ใช้ทั่วไป (P0)

**US-B1** ในฐานะ Guest/User ฉันต้องการดูรายการบริการ subscription ในไทย เพื่อเปรียบเทียบราคา
- แสดงเป็นการ์ด: โลโก้ ชื่อ หมวดหมู่ และราคาเริ่มต้นเป็นเงินบาท
- ค้นหาจากชื่อได้ และกรองตามหมวด (ดูหนัง/ฟังเพลง/เก็บไฟล์/ทำงาน/เกม/อื่น ๆ) ได้

**US-B2** ในฐานะ Guest/User ฉันต้องการดูรายละเอียดบริการ
- แสดงแพ็กเกจทั้งหมด (ชื่อแพ็กเกจ ราคา รอบบิล จำนวนผู้ใช้สูงสุด) และวันที่อัปเดตข้อมูลล่าสุด
- แสดงวิธียกเลิกแบบทีละขั้นตอน
- (P1) แสดงประวัติการเปลี่ยนราคาเป็นกราฟ
- Given เข้าสู่ระบบแล้ว Then มีปุ่ม "เพิ่มเข้ารายการของฉัน" ซึ่งเติมข้อมูลแพ็กเกจให้อัตโนมัติ

### C. จัดการ subscription ของตัวเอง (P0)

**US-C1** ในฐานะ User ฉันต้องการเพิ่ม subscription
- เลือกจากคลังข้อมูล หรือเพิ่มเองแบบ custom (กรณีบริการไม่มีในคลัง)
- ฟิลด์: บริการ, แพ็กเกจ, ราคา, รอบบิล (รายเดือน/รายปี), วันตัดเงินถัดไป, ช่องทางจ่าย (ข้อความ เช่น "บัตร KBank"), วันหมดทดลองใช้ฟรี (ไม่บังคับ), หมายเหตุ
- Given ราคาติดลบหรือไม่ได้กรอกวันตัดเงิน When บันทึก Then แสดง error ที่ช่องนั้น

**US-C2** ในฐานะ User ฉันต้องการดู แก้ไข ยกเลิก และลบ subscription
- ยกเลิก = เปลี่ยนสถานะเป็น `cancelled` (เก็บประวัติไว้) ส่วนลบ = ลบออกจากระบบ ต้องกดยืนยันก่อน
- Given ถึงวันตัดเงินแล้ว Then ระบบเลื่อนวันตัดเงินถัดไปตามรอบบิลให้อัตโนมัติ

### D. Dashboard ผู้ใช้ (P0)

**US-D1** ในฐานะ User ฉันต้องการเห็นภาพรวมค่าใช้จ่าย
- การ์ดสรุป: ยอดรวมต่อเดือน, ยอดรวมต่อปี (แปลงรายปีเป็นรายเดือนให้), จำนวนรายการที่ยังใช้งาน
- กราฟสัดส่วนค่าใช้จ่ายแยกตามหมวด
- รายการที่จะตัดเงินใน 7 วันข้างหน้า เรียงตามวัน
- Empty state: ถ้ายังไม่มี subscription ให้แสดงปุ่มชวนเพิ่มรายการแรก

**US-D2** ในฐานะ User ฉันต้องการดูปฏิทินวันตัดเงิน
- ปฏิทินรายเดือน แต่ละวันแสดงโลโก้และยอดเงินที่จะถูกตัด
- กดวันที่แล้วเห็นรายละเอียดของวันนั้น

### E. การแจ้งเตือน (P0)

**US-E1** ในฐานะ User ฉันต้องการได้รับอีเมลก่อนถูกตัดเงิน
- ตั้งค่าได้: เปิด/ปิดการแจ้งเตือน และแจ้งล่วงหน้า 1/3/7 วัน (ค่าเริ่มต้น 3 วัน)
- ระบบเช็กทุกวันตอน 08:00 แล้วส่งอีเมลผ่าน Gmail SMTP
- อีเมลมี: ชื่อบริการ ยอดเงิน วันตัดเงิน และลิงก์ไปหน้าวิธียกเลิก
- Given ส่งแจ้งเตือนรอบบิลนั้นไปแล้ว Then ห้ามส่งซ้ำ

**US-E2** ในฐานะ User ฉันต้องการได้รับแจ้งเตือนก่อนช่วงทดลองใช้ฟรีหมด
- Given มีวันหมดทดลองใช้ฟรี Then แจ้งล่วงหน้าตามที่ตั้งค่าไว้ ด้วยข้อความ "จะเริ่มเก็บเงินแล้ว ยกเลิกตอนนี้ถ้าไม่ใช้ต่อ"

**US-E3** ในฐานะ User ฉันต้องการเห็นการแจ้งเตือนในเว็บด้วย
- ไอคอนกระดิ่งแสดงจำนวนการแจ้งเตือนที่ยังไม่ได้อ่าน และกดแล้วเห็นรายการ

**US-E4** (สำหรับ demo) มีปุ่ม "ส่งอีเมลทดสอบตอนนี้" ในหน้าตั้งค่า เพื่อสั่งให้ระบบส่งทันทีโดยไม่ต้องรอ 08:00

### F. หารค่าบริการกับเพื่อน (P1 — ฟีเจอร์เด่น)

**US-F1** ในฐานะ User (เจ้าของแพ็กเกจ) ฉันต้องการสร้างกลุ่มหารค่าบริการ
- เลือก subscription ที่จะหาร ใส่ PromptPay ID ของตัวเอง (เบอร์โทรหรือเลขบัตรประชาชน) และเพิ่มสมาชิก (ชื่อ + อีเมล โดยสมาชิกไม่จำเป็นต้องมีบัญชีในระบบ)
- เลือกวิธีหารได้: หารเท่ากันอัตโนมัติ หรือกำหนดยอดเองรายคน

**US-F2** ในฐานะเจ้าของกลุ่ม ฉันต้องการให้เพื่อนสแกนจ่ายส่วนของตัวเอง
- สมาชิกแต่ละคนมี QR พร้อมเพย์ที่ใส่ยอดเงินไว้แล้ว (ตามมาตรฐาน EMVCo)
- Given สแกน QR ด้วยแอปธนาคาร Then แสดงชื่อผู้รับและยอดเงินถูกต้อง
- มีลิงก์ให้แชร์หน้าจ่ายเงินของแต่ละคนได้ โดยไม่ต้องเข้าสู่ระบบ (ลิงก์เป็น token ที่เดาไม่ได้)

**US-F3** ในฐานะเจ้าของกลุ่ม ฉันต้องการติดตามว่าใครจ่ายแล้ว
- ตารางสถานะรายเดือน (จ่ายแล้ว/ยังไม่จ่าย) ที่เจ้าของกดทำเครื่องหมายเองได้
- (P1) ส่งอีเมลเตือนสมาชิกที่ยังไม่จ่าย

### G. ตัวช่วยประหยัด (P1)

**US-G1** ในฐานะ User ฉันต้องการคำแนะนำให้ประหยัดขึ้น
- ถ้าบริการมีแพ็กเกจรายปีที่ถูกกว่า ให้แสดงว่า "เปลี่ยนเป็นรายปีจะประหยัดได้ X บาท/ปี"
- ถ้ามี Family Plan ให้แสดงว่า "ถ้าหารกับเพื่อน N คน จะเหลือ X บาท/เดือน"
- คำนวณจากข้อมูลแพ็กเกจในคลัง (ใช้สูตรคำนวณ ไม่ใช้ AI)

### H. หลังบ้าน Admin (P0)

**US-H1** ในฐานะ Admin ฉันต้องการจัดการหมวดหมู่ (CRUD)

**US-H2** ในฐานะ Admin ฉันต้องการจัดการบริการ (CRUD)
- ฟิลด์: ชื่อ, หมวด, โลโก้ (URL), เว็บไซต์, วิธียกเลิก (ข้อความหลายบรรทัด/markdown)
- Given ลบบริการที่มีผู้ใช้ผูกอยู่ Then ระบบไม่ยอมให้ลบ และแนะนำให้ซ่อนแทน (`is_active = false`)

**US-H3** ในฐานะ Admin ฉันต้องการจัดการแพ็กเกจของแต่ละบริการ (CRUD)
- Given แก้ราคาแพ็กเกจ Then ระบบบันทึกราคาเดิมลงประวัติราคาโดยอัตโนมัติ

**US-H4** ในฐานะ Admin ฉันต้องการดูและจัดการผู้ใช้
- ดูรายชื่อผู้ใช้ ค้นหา และระงับหรือเปิดใช้งานบัญชี (ดูได้เฉพาะข้อมูลบัญชี ไม่เห็นรายการ subscription ส่วนตัวของผู้ใช้)

**US-H5** ในฐานะ Admin ฉันต้องการดู Dashboard ภาพรวมระบบ
- การ์ดสรุป: จำนวนผู้ใช้, จำนวน subscription ที่ใช้งานอยู่, ค่าใช้จ่ายเฉลี่ยต่อผู้ใช้ต่อเดือน, จำนวนอีเมลที่ส่งเดือนนี้
- กราฟ: Top 10 บริการที่คนสมัครมากที่สุด, สัดส่วนตามหมวด, จำนวนผู้ใช้ใหม่รายวัน
- (P1) บริการที่ถูกหารกันมากที่สุด

### I. ข้อกำหนดที่ไม่ใช่ฟีเจอร์ (P0)
- Responsive: mobile-first ใช้งานได้ตั้งแต่ 375px ถึง 1440px
- Accessibility: contrast ผ่าน WCAG AA, ใช้งานด้วยคีย์บอร์ดได้, ฟอร์มมี label ครบ
- ความปลอดภัย: hash รหัสผ่าน, validate ข้อมูลฝั่ง server, ตรวจสิทธิ์ทุก API, เก็บ secret ไว้ใน `.env` เท่านั้น
- ภาษา: UI ภาษาไทย, สกุลเงินบาท, วันที่แบบไทย

## 5. ข้อมูลหลักในระบบ (สำหรับ system-architect ออกแบบต่อ)

```
users ─┬─< user_subscriptions >── plans >── services >── categories
       │          │                            │
       │          ├─< notifications            └─< price_history (ผูกกับ plans)
       │          │
       └─< share_groups ──< group_members ──< member_payments
```

- `users` — role (user/admin), สถานะบัญชี, การตั้งค่าแจ้งเตือน, PromptPay ID
- `categories`, `services`, `plans`, `price_history` — คลังข้อมูลที่ Admin ดูแล
- `user_subscriptions` — รายการที่ผู้ใช้สมัคร (ผูกกับแพ็กเกจในคลัง หรือเป็นแบบ custom)
- `notifications` — ประวัติการแจ้งเตือน (ประเภท ช่องทาง สถานะ อ่านแล้วหรือยัง) และใช้กันส่งซ้ำ
- `share_groups`, `group_members`, `member_payments` — ระบบหารค่าบริการ

**CRUD ที่ตารางสัมพันธ์กัน (ตามโจทย์ ≥ 2 ตาราง):** ฝั่ง Admin ได้แก่ `categories`, `services`, `plans` และฝั่งผู้ใช้ได้แก่ `user_subscriptions`, `share_groups`
